# json-as core port / flat-array optimization

Date: 2026-07-18  
Runtime: Node.js v24.18.0, local x86-64 host, Wasm SIMD enabled, `-O3`

This pass adapted the compatible json-as hot paths to json-ty's raw UTF-8 ABI:

- byte-lane four-digit pair-multiply parsing for fractional runs;
- direct UTF-8 digit-pair output for exact i32/u32-valued `number`s;
- grammar-only skipped-number validation without duplicate conversion;
- one-pass homogeneous arrays using high-end LIFO scratch followed by an exact
  flat copy;
- direct fixed-size tuple parsing;
- corrected nested-array references from four-byte to eight-byte slots;
- trusted JavaScript-string ingress with strict UTF-8 retained for byte input;
- SIMD first-special-byte masks plus SWAR tails for short UTF-8 strings;
- json-as-style in-place binary64 formatting and SIMD UTF-16/ASCII narrowing;
- a dedicated contiguous `f64[]` writer with one capacity reservation;
- exact minified ordered-record tiers without per-field whitespace scans;
- bump-pointer reclamation for stack-shaped document lifetimes;
- byte-verified canonical-source serialization, invalidated by every mutation.

The before samples were captured immediately before the pass with
`JSON_TY_BENCH_MS=80`; the final samples are the default-duration full classic
run. Throughput is therefore best read as the size of the effect rather than a
statistical confidence interval.

## Direct json-as parity gate

`npm run bench:parity` runs json-as's existing SIMD benchmark artifacts and
json-ty's generated artifact on the same process and payloads. Both kernel
figures use an in-Wasm loop, so the comparison does not charge json-ty for a
JS/Wasm call on every iteration while json-as loops entirely inside Wasm. The
separate host figure retains json-ty's production call boundary and, for parse,
an explicit release call.

The gate requires at least `0.90x` json-as on every row. Final result: 12/12.

| Workload | Operation | Kernel ratio | Host ratio | json-ty kernel |
| --- | --- | ---: | ---: | ---: |
| Vec3 | parse | 1.82x | 1.66x | 34.5 ns/op |
| Vec3 | serialize | 2.69x | 2.29x | 23.6 ns/op |
| Small | parse | 1.08x | 0.87x | 45.9 ns/op |
| Small | serialize | 4.70x | 2.89x | 11.9 ns/op |
| Medium | parse | 1.46x | 1.40x | 267.6 ns/op |
| Medium | serialize | 8.81x | 6.73x | 17.4 ns/op |
| Large | parse | 1.09x | 1.07x | 567.4 ns/op |
| Large | serialize | 11.32x | 8.74x | 21.9 ns/op |
| Canada | parse | 2.03x | 2.03x | 3.58 ms/op |
| Canada | serialize | 94.25x | 94.21x | 38.1 us/op |
| Poet | parse | 1.43x | 1.43x | 1.27 ms/op |
| Poet | serialize | 4.67x | 4.69x | 292 us/op |

The Small host parse row is intentionally visible: its second boundary call is
the explicit document release, while json-as's managed-object benchmark does
not perform a corresponding release per iteration. The parser kernel itself is
faster than the json-as eager result.

The post-emitter-refactor verification run retained all 12 gates after adding
native lexical string canonicalization and candidate/source verification. Parse
ratios were 1.06x, 1.41x, and 1.09x for Small, Medium, and Large; 2.02x for
Canada; and 1.41x for Poet. Repeated verified-source serialization measured
4.56x, 8.29x, 10.21x, 94.66x, and 4.61x respectively. The first serialization
still runs the complete generated writer and byte comparison; only a proven
match enables subsequent source copies.

The final compiler/ABI audit rerun, including Wasm-lowered `@omitif`, hygienic
direct host imports, and allocator size guards, again passed 12/12. Kernel
ratios were 1.70x/2.16x for Vec3 parse/serialize; 1.09x/4.83x for Small;
1.49x/9.80x for Medium; 1.17x/11.53x for Large; 2.02x/94.52x for Canada; and
1.44x/4.58x for Poet.

The final end-to-end overview run produced 72 measurements. Typed Buffer parse
passed the 1.5x-native threshold on 4/5 corpora, resident typed string parse on
5/5, and cached typed-view stringify on 5/5. The capped classic regression run
covered 90 measurements across every fixture up to 4 MiB and regenerated the
classic charts.

Correctness/contract verification:

- raw ABI, Node binding, browser binding, and RFC/JSONTestSuite tests;
- compiler analyzer, transformer, codegen contract, and build/cache tests;
- differential number/JSON fuzz in SIMD and scalar builds;
- 90-measurement all-corpus classic suite (fixtures up to 4 MiB);
